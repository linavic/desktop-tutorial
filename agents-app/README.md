# צוות הסוכנים: מערכת תוכן לכל עסק

אפליקציית ווב שעובדת על **OpenAI בלבד**. מגדירים את העסק פעם אחת, מקלידים משימה, ושמונה סוכנים עובדים בשרשרת בזמן אמת: חוקרים ברשת, כותבים, מעצבים תמונות ומעבירים אחד לשני. רואים מי עובד עכשיו, מה הוא קיבל, מה הוא כותב ומה הוא מעביר הלאה.

המערכת כללית. Etel Clinic הוא רק פרופיל לדוגמה בתוך `profiles.json`, ואפשר למחוק אותו.

## התחלה מהירה
```
cd agents-app
node server.js                        # מצב הדגמה, בלי מפתח
OPENAI_API_KEY=sk-... node server.js  # מצב חי
```
פותחים http://localhost:3000.
1. **העסק שלך:** בוחרים תבנית (מסעדה, נדל"ן, רואה חשבון, חנות אונליין, כושר, או Etel Clinic לדוגמה) או ממלאים מאפס: שם, תחום, מה מציעים, קהל, טון, שפה וכללים שחובה לכבד. נשמר בדפדפן.
2. **חיבור:** מדביקים מפתח OpenAI (או מגדירים `OPENAI_API_KEY` בשרת), ואפשר להעלות עד 3 תמונות reference לסגנון המותג.
3. מקלידים משימה ומשגרים.

## מה המערכת עושה
- **8 סוכנים בשרשרת:** מנהל → חן → חוקר → כותב → יעל → יובל → עורך → מפיץ. הסוכנים נטענים מקבצי ההגדרה ב-`agents/*.md`, וההעברה ביניהם נעשית דרך קבצים (`runs/<runId>/`, לא נכנס ל-git).
- **חיפוש חי ברשת:** חן והחוקר משתמשים בכלי `web_search` של OpenAI (Responses API). המקורות האמיתיים מופיעים בזמן הריצה, ונכנסים לקבצים.
- **תמונות:** יובל מנסח prompts ומייצר תמונות עם `gpt-image-2` (1024x1024, medium), עד 2 לריצה. ה-placeholders של יעל מוחלפים בתמונות לפני שהטקסט עובר לעורך.
- **ערכת מותג (בהגדרת העסק):**
  - **Reference לסגנון:** עד 3 תמונות של העסק או הסגנון הרצוי. מודל ראייה מנתח אותן, והסגנון מוזן ליובל ולכל prompt של תמונה. הניתוח מוצג בכרטיס של יובל.
  - **לוגו:** הלוגו האמיתי לא נשלח למודל (מודלי תמונות ממציאים לוגואים). הוא מודבק על התמונות בדפדפן בפינה שנבחרה, ונכנס גם להורדת ה-HTML. ה-prompts של יובל מורים למודל לא לצייר טקסט, אותיות או לוגו.
  - נשמר בדפדפן (localStorage), לכן כדאי תמונות קטנות.
- **פרואקטיבי:** כפתור "סרוק טרנדים עכשיו" מחפש ברשת רעיונות חמים לעסק שלך, ומשגר כל אחד בלחיצה. בסוף כל משימה המנהל מציע 3 משימות המשך.
- **תוצר מוכן:** מאמר מעוצב עם התמונות, העתקה, הורדה כקובץ HTML עצמאי (התמונות מוטמעות), הורדת כל הקבצים, והיסטוריית משימות בדפדפן.

## התאמה לעסק חדש (מי שרוכש ומפעיל)
- **בדף:** מגדירים את העסק פעם אחת. הכותרת, ההקשר והתמונות משתנים בהתאם.
- **שם המותג בכניסה:** `BRAND_NAME="שם העסק"` (ברירת מחדל `Agent Crew`).
- **הקשר ברירת מחדל מהשרת:** קובץ `context.md` בתיקיית האפליקציה, או `CONTEXT_FILE=נתיב`. משמש כשלא הוגדר הקשר בדף.
- **תבניות לתחומים נוספים:** מוסיפים אובייקט ל-`profiles.json` (שם, תחום, מה מציעים, קהל, טון, שפה, כללים ודוגמאות משימה).
- **מפתח:** כל עסק מפעיל מופע משלו ומזין את המפתח של עצמו. אם מגדירים `OPENAI_API_KEY` בשרת, כל מי שנכנס עם הסיסמה משתמש במפתח הזה ובעלות עליו.

## מה רואים במסך
שורת משימה זוהרת, רקע חי שמגיב לעבודה, צומת לכל סוכן עם טבעת מסתובבת ונקודת אור שעוברת בקו עם שם הקובץ, טיקר של מה שהסוכן כותב עכשיו, רצועת חיפוש חי עם שאילתות ומקורות, כרטיס הסוכן הפעיל עם פלט בסטרימינג וגלריית תמונות, יומן פעילות, וקונפטי בסיום.

## מגבלות (חשוב)
- **נבדק מול שרת OpenAI מדומה בלבד.** הקוד מדבר עם `/v1/chat/completions`, `/v1/responses` (עם `web_search`, ואם נדחה אז `web_search_preview`) ו-`/v1/images/generations`. לא נבדק מול OpenAI האמיתי. שמות אירועים, זמינות הכלים וההרשאות של המפתח עלולים להשתנות, ובמקרה כזה תופיע שגיאה בדף.
- **חיפוש וגם תמונות תלויים בחשבון:** חיפוש ברשת דורש מודל וחשבון שתומכים ב-`web_search`, ותמונות דורשות גישה ל-`gpt-image-2`. אם החיפוש נכשל, הסוכנים ממשיכים בלי חיפוש ומסמנים זאת. לכל חיפוש ולכל תמונה יש עלות ב-OpenAI.
- **הסוכנים הם קריאות למודל עם קובץ ההגדרה כ-system prompt.** חוץ מחיפוש ברשת אין להם גישה למערכת קבצים או לכלים. יעל מחזירה Markdown בלבד, בלי HTML.
- **רשימת הצעדים בכרטיס** מסומנת כשהסוכן מסיים. מה שמתקדם בזמן אמת הוא הפלט המוזרם.
- **המפיץ לא מפרסם בפועל.** הוא מכין התאמות וצ'קליסט.
- **כללי רגולציה:** ההקשר נותן לסוכנים כללים לכבד, אבל לא מחליף בדיקה של אדם. תוכן בתחומים מוסדרים (רפואה, פיננסים, משפט) דורש אישור לפני פרסום.
- **במצב הדגמה** הטקסטים קבועים והתמונות הן איורי SVG.

## סיסמת כניסה
- בלי `APP_PASSWORD` השרת מאזין רק ל-`localhost`.
- עם `APP_PASSWORD=סיסמה_ארוכה` השרת נפתח לרשת ודורש התחברות. אחרי 5 ניסיונות שגויים יש נעילה של 15 דקות.
- `APP_SECRET` (לא חובה) מקבע את חתימת ההתחברות בין הפעלות.
- להריץ מאחורי HTTPS (למשל Render), כדי שהסיסמה והמפתח לא יעברו גלויים.

## פריסה ל-Render
`render.yaml` בשורש הריפו מגדיר שירות. ב-Render: New → Blueprint → הריפו → מזינים `APP_PASSWORD` (ואפשר `BRAND_NAME`) → Apply.

## משתני סביבה
`OPENAI_API_KEY`, `OPENAI_MODEL` (ברירת מחדל `gpt-4.1`), `OPENAI_BASE_URL`, `BRAND_NAME`, `CONTEXT_FILE`, `APP_PASSWORD`, `APP_SECRET`, `PORT`.
